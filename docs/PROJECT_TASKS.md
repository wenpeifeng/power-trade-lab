# 项目任务与交付契约

本文规定 Power Trade Lab 的任务拆分、验证证据和完成报告格式。它借鉴飞书大脑项目的任务 brief/report 结构，但按本项目“数据与规则 → 学习与考试 → 仿真 → 复盘回流”的产品闭环重新划分。

## 1. 每个任务开始前必须冻结

任务 brief 至少包含：

1. **目标与用户场景**：解决谁的什么问题，落在产品闭环哪一环。
2. **Files**：明确 Create / Modify / Test 文件，避免边做边扩大范围。
3. **Interfaces**：请求、响应、数据模型、状态变化和错误语义。
4. **Evidence**：规则原文、公开数据来源、源码调用链或真实失败案例。
5. **Safety**：权限、凭证、个人数据、版权、外部调用和降级边界。
6. **Acceptance**：可以自动运行、可以证伪的完成条件。

## 2. 标准执行步骤

```text
Step 1  写失败测试或冻结可复现基线
Step 2  运行并确认按预期失败
Step 3  实现最小且通用的机制
Step 4  跑直接测试、同类泛化测试和反例
Step 5  跑受影响模块与端到端回归
Step 6  形成 report，记录提交、证据、风险和遗留项
```

不得为单个页面、账号、省份、文档标题或样本写生产硬编码。真实失败案例可以进入测试夹具，但不能进入生产判断条件。

## 3. 当前任务主线

### T1 数据与规则底座

- **Produces**：数据源目录、来源等级、采集记录、规则版本和质量状态。
- **Consumes**：官方页面/API、用户合法授权文件或明确标注的重构/合成数据。
- **完成条件**：来源、许可、业务日期、抓取时间、内容哈希齐全；增量、去重、失败重试和撤销路径可验证。

### T2 学习与考试

- **Produces**：引导课程、题目、考试、错题、掌握度和引用证据。
- **Consumes**：T1 中有来源的知识点、规则和教材。
- **完成条件**：学习/考试反馈边界正确，断点恢复与判分可复现，权限隔离和引用回链通过。

### T3 仿真交易

- **Produces**：场景、主体、资产、申报、出清、结算和复盘。
- **Consumes**：版本化规则、输入数据、随机种子和订单集合。
- **完成条件**：24/96 点、多段量价、边界约束、部分成交、撤改单、资金与电量守恒、同种子确定性全部有测试。

### T4 跨模块回流

- **Produces**：由考试或仿真证据驱动的薄弱点、课程/题目推荐和下一次训练任务。
- **完成条件**：至少一个真实纵向案例从输入到复盘再回到学习，且每一步可追踪、可重放。

### T5 数据接入与安全

- **Produces**：公开数据连接器、授权数据连接器、凭证引用和撤销记录。
- **完成条件**：双用户隔离、默认拒绝、日志脱敏、密钥不出服务端、撤销后停止同步；不绕过登录、验证码或访问控制。

### T6 安装与发布

- **Produces**：可复现依赖、启动/停止脚本、配置模板、发布清单和回滚说明。
- **完成条件**：在全新 clone 中完成安装、启动、`/health`、`/api/health`、前端访问、注册/登录和重复启停；仓库泄密检查通过。

## 4. 任务完成报告模板

```markdown
### Task N: 标题

- 状态：PASS / PARTIAL / BLOCKED / NOT_RUN
- Commit：<sha>
- 改动文件：...
- 根因或目标：...
- 实现机制：...
- 测试命令与结果：...
- 安全与数据确认：...
- 尚未成立的结论：...
- 后续任务：...
```

`PARTIAL` 不能在 README、发布说明或界面中改写成“已完成”。不能运行的测试必须写明原因和影响范围。

## 5. 提交前最小检查

```bash
python3 scripts/open_source_check.py
backend/.venv/bin/python -m compileall backend/app backend/crawlers
cd frontend && npm run build
```

涉及后端行为时还必须运行受影响测试；涉及交易引擎、考试引擎、RAG 或跨模块链路时，按 `AGENTS.md` 和 `docs/评估体系与回归测试规范.md` 执行对应评估。
