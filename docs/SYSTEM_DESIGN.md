# Power Trade Lab：系统入口与视觉规范

## 1. 信息架构

门户只展示一级系统，不把页面、工具和系统混在同一层：

| 一级系统 | 用户目标 | 核心入口 | 系统内服务 |
| --- | --- | --- | --- |
| 学习中心 | 从零建立业务认知并形成能力证据 | `/learn` | 引导学习、刷题、考试、错题、教材 |
| 仿真交易 | 在安全环境完成一轮可复盘交易 | `/trade/lab` | 行情终端 `/trade`、申报、出清、结算、复盘 |
| 知识库 | 找到可信规则、政策和业务解释 | `/knowledge` | AI 问答 `/assistant`、政策公告 `/policy` |
| 数据资产 | 让真实数据持续接入并保持可信 | `/asset` | 质量治理、接入、采集任务、时间线 |

数据运维是数据资产的默认一级工作区，不属于知识库深层页面。知识库只提供直达入口。

## 2. 色彩职责

- 门户：中性靛蓝 `#4F5BD4`。负责系统编排，不继承任何单一子系统色。
- 学习：成长靛蓝 `#4F5BD4`，辅以少量青色。表达路径、掌握度和反馈。
- 仿真交易：深海军蓝背景，交易蓝、数据青和风险琥珀。表达高密度行情与执行。
- 知识库：索引钴蓝 `#4168DC` + 认知青 `#16A6A9`。表达检索、引用和关联。
- 数据资产：电气蓝 `#1976D2` + 实时青 `#08A99A`。表达流入、治理、可信和追溯。
- 政策与 AI 不建立新主题，继承知识库主题。

禁止在同一系统内用多个无关大面积底色区分普通卡片。状态色只用于状态线、数字、标签和告警。

## 3. 入口规范

1. 每个一级系统必须有醒目的“返回门户”。
2. 系统页只展示强关联的跨系统入口：
   - 学习 → 仿真实操
   - 仿真 → 学习补强、知识查询
   - 知识 → 数据运维、AI、政策
   - 数据 → 知识检索、AI
3. 当前页面不能错误显示为其他系统的选中状态。
4. 只读统计不得使用按钮式悬浮反馈；可点击入口必须有 hover、focus 和 active。

## 4. 动效规范

- 每页只保留一个主动态视觉，例如能力轨道、知识雷达或数据管道。
- 数字进入页面时允许计数动画；状态点允许低频脉冲；列表仅做轻微位移和状态线反馈。
- 动效必须支持 `prefers-reduced-motion`。
- 不使用无业务含义的随机漂浮、连续缩放和整页发光。

## 5. 页面验收

- 进入页面 3 秒内能辨认所属系统和主任务。
- 返回门户与下一步操作无需滚动即可找到。
- 同类数据用统一容器；不同业务队列必须通过标题、说明和状态标识区分。
- 所有原文、来源和日期保持可追踪。
- 1440、1024、移动端均不得横向溢出或因滚动条导致导航抖动。
