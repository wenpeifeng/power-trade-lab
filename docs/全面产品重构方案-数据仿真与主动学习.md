# 全面产品重构方案：数据资产、专业仿真与主动学习

> 本方案基于 2026-07-23 的仓库实现、当前开发数据库、ElecSim V8 公开文档和现行电力市场基础规则整理。它定义产品应该成为怎样的系统，以及按什么顺序实施；不把竞品菜单数量当作完成度。

## 1. 产品结论

本产品不应只是“行情看板 + 刷题 + 简单买卖”，而应成为个人学习者可长期使用的电力交易训练环境：

```text
真实规则与公开数据
  → 结构化知识与课程
  → 主动学习和能力诊断
  → 带任务的历史场景仿真
  → 申报、出清、结算与风险分析
  → 证据化复盘
  → 自动安排下一次学习和训练
```

三个核心资产同等重要：

1. **数据资产**：来源明确、持续更新、可追溯、可重放。
2. **规则与知识资产**：国家规则、省级细则、教材、案例和术语相互关联。
3. **行为与能力资产**：学习、答题、预测、报价、结算和复盘形成可解释的能力画像。

用户是个人学习者，不具备企业级交易账号。产品设计必须接受这个边界：国内分钟级、主体级和私有结算数据通常不能获得，但公众披露、历史报告、规则、D+1 聚合运行数据、气象、能源统计以及依法公开的交易结果，足以搭建面向国内电力市场的高质量学习和仿真底座。

## 2. 当前系统的真实完成度

### 2.1 当前数据库事实

开发数据库中的主要学习资产：

| 对象 | 数量 | 结论 |
|---|---:|---|
| 知识点 | 8 | 只有入门级粗粒度目录 |
| 课程 | 0 | 尚未形成课程体系 |
| 课时 | 0 | 尚无可学习的教学单元 |
| 题目 | 20 | 只能支持演示级刷题 |
| 学习记录 | 0 | 尚未形成课程进度证据 |
| 学习路径 | 0 | 路径模型没有实际运行 |
| 知识文档 | 73 | 已有资料基础 |
| 文档切片 | 390 | 已有检索基础，但不等于课程 |

当前“开始学习”最终跳转到刷题；8 个固定入门步骤没有配套课程、阅读、实验、项目和稳健的掌握度更新。8 道随机诊断题不足以精确判断一个人的真实能力。

### 2.2 当前交易链路

当前交易模块本质是：

```text
选择市场/省份/日期
  → 查看一条 96 点曲线
  → 输入单个价格和电量
  → 调用同一套简化随机虚拟流动性逻辑
  → 立即生成成交和简单复盘
```

主要缺口：

- 中长期、日前、实时、调频和绿电只是不同入口，底层没有独立机制。
- 没有仿真任务、市场时钟、申报窗口、封盘、出清、结算状态机。
- 没有 96 点多段量价申报、机组/负荷/储能资产和物理约束。
- 部分成交的订单状态、账户、冻结资金和持仓没有完整对账。
- 没有合同—日前—实时—实际用电—偏差结算的贯通链路。
- 没有规则条款、引擎版本和输入快照，结果无法严格审计和复现。

因此，当前适合称为“交易交互原型”，不应称为完整电力市场仿真系统。

## 3. ElecSim 能力与我们的目标边界

ElecSim 公开文档显示，其专业仿真底座已经包括：

- 单人和多人仿真、多房间、多日 D1—D5。
- 管理员分配用户、机组和负荷，控制交易阶段与报价计时。
- 网络、机组、负荷、新能源预测、负荷预测和备用等信息设置。
- 双边合约、集中竞价、日前和实时流程。
- 现货分时多段报价、启停/空载费用和批量智能报价。
- SCUC、SCED、节点边际电价、潮流、机组/负荷/母线结果。
- 基础场景与当前场景的收入、利润、价格和运行结果对比。

这些能力是可信专业仿真的底线，但不代表我们的产品应该照抄其信息架构。

| 能力 | 当前项目 | 应达到的目标 |
|---|---|---|
| 单人历史回放 | 简化随机撮合 | 真实日数据快照、确定性回放、对比真实结果 |
| 主体与资产 | 账户骨架 | 发电、售电、用户、储能、VPP 与约束模型 |
| 市场流程 | 提交后立即成交 | 准备、申报、封盘、出清、结算、复盘状态机 |
| 中长期 | 标签 | 双边、集中竞价、滚动撮合、挂牌和合同转让 |
| 现货 | 单段报价 | 96 点多段报价、SCUC/SCED、统一/分区/节点价格 |
| 结算 | 简单潜在盈亏 | 合同、现货、偏差、辅助服务、追退补可对账结算 |
| 风险 | 无 | 敞口、VaR/压力测试、价格/负荷/新能源风险 |
| 数据 | 重构曲线为主 | 公开观测、授权观测、重构、合成四级血缘 |
| 规则 | 无版本 | 国家—省份—品种—生效期规则包与条款引用 |
| 教学 | 刷题为主 | 课程、教材、实验、仿真、复盘和间隔复习闭环 |

我们需要在专业出清能力之外增加四项差异化能力：

1. **数据可信**：所有数字能回到原网页、文件、接口响应和解析版本。
2. **规则可信**：计算结果能指出适用规则、版本、公式和条款。
3. **学习主动**：系统每天告诉用户学什么、为什么学、练到什么程度。
4. **训练贴近岗位**：不只研究电网优化，还覆盖预测、合同、持仓、结算、风险、信息披露和复盘。

### 3.1 房间不是个人版的前置条件

房间的用途是把教师、学员、市场主体、统一时钟和同一案例组织起来，用于多人博弈、竞赛和带班教学。个人学习默认使用 `SimulationRun`，一键开始历史场景或教学案例，不需要先创建房间。

多人能力应建立在已经稳定的单人引擎上：

```text
SimulationRoom
  └─ 组织用户、角色和共享时钟
       └─ 调用同一个 SimulationRun / ClearingEngine / SettlementEngine
```

## 4. 个人学习者的数据资产策略

### 4.1 不把“实时”当作一个模糊标签

前端统一显示数据时效：

| 时效等级 | 定义 | 典型用途 |
|---|---|---|
| `live` | 秒级至 15 分钟，来自许可的持续接口 | 国内气象实况、预警等辅助数据 |
| `near_real_time` | 15 分钟至数小时 | 负荷、出力、价格、系统运行 |
| `D+1` | 次日披露 | 国内现货聚合结果和运行信息 |
| `periodic` | 周、月、季度、年度 | 市场规模、交易均价、能源结构 |
| `historical` | 固化历史文件或数据集 | 回放、回测、教学案例 |
| `reconstructed` | 由公开统计和约束重建 | 缺失字段补全，不能冒充观测 |

国内《电力市场信息披露基本规则》把信息分为公众、市场成员公开和特定信息。个人版只能默认自动采集公众信息。某省实施细则即使规定 D+1 披露，也不等于所有明细都向匿名公众开放。

### 4.2 首批数据源目录

#### 国内主线：理解中国规则和市场

| 数据源 | 可获取内容 | 常见时效 | 接入方式 |
|---|---|---|---|
| 国家发展改革委、国家能源局及派出机构 | 基础规则、政策、监管通报、省级细则 | 发布即更新 | 公开网页/PDF |
| 国家能源局统计 | 市场交易电量、电力工业统计 | 月度 | 公开网页/附件 |
| 国家统计局“国家数据” | 分省发电量、能源生产和宏观指标 | 月度/年度 | 公开查询/下载 |
| 北京、广州及省级电力交易中心公众区 | 公告、交易结果、市场报告、绿电信息 | 日/月/不定期 | 公开网页/附件 |
| 省级信息披露平台公众区 | 现货日报、聚合量价、负荷/出力/备用等 | D+1 或更慢 | 公开页面/导出；逐省确认 |
| 中国气象数据网 | 历史日值、逐三小时观测、再分析等 | D+2、日/月或历史 | 个人/教育科研实名注册后检索下载 |
| 国内气象开发服务 | 实况、逐小时预报、格点天气 | 15 分钟至小时 | 开发者 KEY；只作可替换辅助源 |
| 碳市场、煤炭及燃料公开信息 | 碳价、燃料成本代理变量 | 日/周 | 交易所或官方发布 |

国内优先选择一个省份做深，不同时做全国。首省应满足：

- 现货连续运行或公开试运行数据较丰富。
- 规则、日报或交易结果公开入口稳定。
- 能得到至少价格、负荷、新能源或市场总量中的两类时间序列。
- 用户有明确学习兴趣。

候选优先级可从山西、山东、广东、浙江中通过一周的连接器可用性验证确定，不能只按市场知名度决定。

#### 国内数据获取矩阵

| 数据类别 | 普通个人能否获取 | 推荐方式 | 产品处理 |
|---|---|---|---|
| 国家规则、政策、监管通报 | 可以 | 官网网页/PDF 自动采集 | 版本化、条款化 |
| 省级实施细则、交易公告 | 可以 | 监管机构和交易中心公众区 | 绑定省份和生效期 |
| 公开交易结果、市场报告 | 视省份而定 | 公众页面、附件、公开导出 | 原始文件留存 |
| D+1 聚合量价和运行数据 | 部分省份可得 | 信息披露平台公众区 | 逐省验证字段和稳定性 |
| 市场成员公开信息 | 通常不可以 | 只有合法市场成员账号可访问 | 不绕过权限采集 |
| 主体报价、合同、计量、结算单 | 不可以 | 未来由用户合法导入自己的文件 | 默认私有和隔离 |
| 历史/逐三小时气象 | 可以注册获取 | 中国气象数据网个人实名下载 | 权威历史特征源 |
| 气象实况和预报 API | 可以 | 国内开发者气象服务 KEY | 可替换辅助连接器 |

本项目近期只建设国内数据连接器。国外交易数据不进入产品路线图、默认数据目录和教学案例。

### 4.3 国内账号与 Token 接入原则

国内电力交易数据通常不存在“普通个人注册后即可申请的统一 API Token”。对于个人版：

- 公众页面、公告和附件不需要 Token，按网站许可与频率采集。
- 需要市场主体身份的信息披露账号不作为个人版依赖。
- 中国气象数据网以个人实名检索下载为主，不把它假设为稳定实时 API。
- 如需实时气象，可以使用用户本人申请的国内开发者 KEY。
- 用户未来合法导出的合同、结算和用电文件，通过本地导入，不提取其交易平台登录凭证。

如果某个国内平台确实向用户本人提供合法 API Token，可以为它建设专用连接器，但用户**不要在聊天中粘贴 Token**。

推荐流程：

```text
系统展示官方注册地址和所需权限
  → 用户在官方平台自行注册
  → 本地“数据连接”页调用操作系统钥匙串保存 Token
  → 后端数据库只保存 credential_ref、scope 和过期时间
  → 测试连接并展示可访问数据目录
  → 用户勾选数据集和同步频率
  → 原始响应落盘、哈希、标准化、质检
```

不尝试：

- 借用或购买他人电力市场主体账号。
- 绕过验证码、二次认证、频率限制或权限控制。
- 抓取只向特定经营主体披露的数据。
- 将 Token 写进 `.env` 后提交到仓库，或记录到请求日志。

截图中的旧 SmartWeatherAPI 页面虽然仍能访问，但申请依赖的表格下载入口不可作为稳定产品流程，因此从推荐数据源中移除。替代顺序为：

1. 中国气象数据网个人实名下载，用于权威历史观测和回测。
2. 国内开发者气象 API，用于实况和预报。
3. 缺少 API 时允许用户上传 CSV/Excel，保留来源和获取日期。

### 4.4 数据资产分层

```text
Source Registry
  数据源、许可、披露范围、连接方式、频率和负责人
        ↓
Raw / Bronze
  原网页、PDF、Excel、CSV、JSON、抓取时间、HTTP 元数据、SHA-256
        ↓
Normalized / Silver
  统一市场、区域、时间、时区、间隔、单位、主体和品种
        ↓
Curated / Gold
  96 点曲线、市场日快照、规则包输入、特征和可复用指标
        ↓
Scenario Snapshot
  仿真使用的不可变数据版本
```

每个前端数字至少可展开查看：

```text
来源机构 / 原始链接 / 发布时间 / 抓取时间
观测或重构 / 披露范围 / 时间粒度 / 单位
原始文件哈希 / 解析器版本 / 质量状态 / 修订记录
```

## 5. 完整专业仿真系统

### 5.1 业务对象

```text
RulePackage
  国家基础规则 + 省级细则 + 参数 + 生效期 + 条款

SimulationCase
  任务目标 + 主体模板 + 资产模板 + 场景数据 + 事件

SimulationRun
  用户角色 + 输入快照 + 阶段 + 申报 + 出清 + 结算 + 复盘

Portfolio
  中长期合同 + 现货计划 + 实际电量 + 辅助服务 + 绿证 + 风险敞口
```

### 5.2 十个完整能力域

#### A. 规则与市场日历

- 国家和省级规则版本、生效/失效时间、修订差异。
- 交易日历、申报窗口、封盘、结果发布、结算周期。
- 规则条款—公式—字段—校验—题目—课程关联。
- 同一历史日自动选择当时有效的规则包。

#### B. 市场主体、组织和权限

- 发电企业、售电公司、电力用户、储能、VPP、微电网。
- 主体准入档案、代理关系、用户与资产分配。
- 单人版可让系统代理其他主体；多人版再引入房间。

#### C. 资产与预测

- 火电、水电、核电、风电、光伏、储能、可调负荷。
- 容量、成本、爬坡、启停、最小开停机、SOC、可用率。
- 负荷、新能源、价格和偏差预测；预测版本和误差评估。
- 检修、非停、联络线、断面、备用和系统事件。

#### D. 中长期市场

- 年/月/月内/周/多日和分时合同。
- 双边协商、集中竞价、滚动撮合、挂牌摘牌。
- 基荷/峰荷/分时曲线、合同转让和合同调整。
- 绿电交易与环境价值、绿证的联合或分开记录。

#### E. 现货市场

- 日前、日内、实时独立阶段和衔接。
- 24/48/96 点、每点多段量价和批量填报。
- 固定费用、启停、空载、容量和物理约束。
- 统一出清、分区价格、节点价格三种教学层级。
- SCUC、SCED、安全校核、阻塞和损耗解释。

#### F. 辅助服务

- 调频、备用、调峰、爬坡等品种。
- 需求发布、容量/里程申报、出清、调用、性能评价。
- 与能量市场的机会成本、联合出清和费用分摊。

#### G. 零售、计量与结算

- 零售套餐、代理合同、用户负荷和实际用电。
- 中长期、日前、实时、偏差和辅助服务结算。
- 节点/统一结算点、输配电价、政府性基金等可配置项目。
- 日清月结、结算单、对账、异议、追退补和规则修订。

#### H. 持仓、风险和策略

- 合同覆盖率、净敞口、分时头寸和现金流。
- 日前—实时价差、偏差风险、新能源预测风险。
- 历史回测、基准策略、压力测试、情景分析和止损提醒。
- 收益归因：价格、数量、合同、偏差、约束和辅助服务。

#### I. 市场监测与合规

- 报价行为、价格尖峰、负电价、阻塞和市场力指标。
- 申报校验、越权、迟报、撤单、异常行为和审计日志。
- 市场干预、限价、应急处置及干预前后结果对比。

#### J. 分析与复盘

- 市场、主体、资产、母线、线路、时段和交易品种视角。
- 用户策略、基准策略、真实结果、最优上界四方对比。
- 每个未成交、约束触发和金额都可解释。
- 自动映射薄弱知识点并创建后续学习任务。

### 5.3 分层引擎，避免一步做成黑箱

| 引擎等级 | 目标 | 适合用户 |
|---|---|---|
| L0 供需曲线 | 单时段统一边际出清、部分成交 | 完全小白 |
| L1 多时段组合 | 96 点、多段申报、简单跨时段约束 | 入门交易员 |
| L2 机组约束 | 启停、爬坡、最小出力、储能 SOC | 进阶 |
| L3 网络约束 | DC 潮流、分区/节点价格、阻塞 | 专业学习 |
| L4 多市场衔接 | 中长期—日前—实时—辅助服务—结算 | 综合实战 |

每一级都应展示输入、公式和结果，不应只给求解器黑箱输出。

## 6. 从刷题中心重构为主动学习系统

### 6.1 主动学习的产品形态

用户进入学习中心时，默认看到的不是知识点列表，而是“今天的学习任务”：

```text
5 分钟回顾旧知识
  → 15 分钟新课
  → 5 分钟例题与即时检查
  → 10 分钟数据观察或小实验
  → 15 分钟仿真任务
  → 3 分钟复盘和下一步安排
```

系统根据先修关系、遗忘曲线、答题表现、阅读行为和仿真错误主动排课。用户仍可自由浏览，但不需要自己规划完整路线。

### 6.2 五阶段入门课程

#### 阶段 0：看懂电力系统

- 发—输—配—用、电力平衡、调度、频率和备用。
- MW、MWh、功率、电量、负荷曲线和 24/48/96 点。
- 火电、新能源、储能和负荷的运行特性。
- 实验：拖动负荷和新能源，观察平衡与备用变化。

#### 阶段 1：看懂电力市场

- 为什么需要电力市场，批发、零售和市场成员。
- 中长期、现货、辅助服务、绿电和绿证。
- 价格形成、边际成本、供需曲线和机会成本。
- 实验：单时段统一边际出清。

#### 阶段 2：会做中长期和零售

- 双边、集中竞价、滚动撮合、挂牌。
- 合同曲线、零售套餐、合同覆盖率和持仓。
- 实验：先签合同，再观察现货价格变化对收益的影响。

#### 阶段 3：会做现货和结算

- 日前、日内、实时、申报、SCUC、SCED。
- 节点价格、阻塞、预测误差和偏差结算。
- 实验：完成一个真实历史日的 96 点报价和结算。

#### 阶段 4：像交易员一样决策

- 负荷/新能源/价格预测，策略、风险和收益归因。
- 储能、VPP、辅助服务、绿电和省份规则差异。
- 项目：连续 7 个市场日管理组合并提交交易日志。

课程等级与《电力交易员国家职业标准（2024 年版）》的职业功能建立映射，但不宣传为官方认证培训。

### 6.3 交易员业务学院

学习系统不仅讲电力原理和市场机制，还要教用户“交易员每天具体做什么”。业务课程以《电力交易员国家职业标准（2024 年版）》的工作职能为主干：

| 业务域 | 必学业务知识 | 必做练习/产物 |
|---|---|---|
| 交易资质与信息管理 | 主体类型、注册/变更/退出、账号权限、信息披露分级 | 审核一套模拟注册资料，识别缺失项 |
| 市场政策与规则解读 | 国家规则、省级细则、交易公告、时间安排和版本差异 | 将一份交易公告转成操作清单 |
| 中长期交易 | 交易计划、合同曲线、双边/竞价/滚动/挂牌、绿电绿证 | 编制月度交易计划和申报方案 |
| 现货交易 | 日前/实时流程、信息披露、负荷/新能源/价格预测、分段报价 | 完成一个历史日 96 点申报 |
| 辅助服务 | 调频、备用、调峰、性能参数、补偿和考核 | 核算一次容量/里程收益与考核 |
| 售电与客户管理 | 客户画像、零售套餐、合同条款、用能服务、电量跟踪 | 设计一个零售套餐并分析风险 |
| 电价分析与结算 | 电能量、辅助服务、市场分摊、偏差考核、账单和对账 | 从原始数据生成并复核结算单 |
| 市场风险与信用 | 合同覆盖率、价格/偏差/信用风险、额度和风险台账 | 建立敞口与风险处置台账 |
| 交易平台操作 | 公告下载、数据上传、报价、结果确认、异常处理 | 在仿真平台完成一次全流程操作 |
| 报告与沟通 | 日报、周报、复盘、客户沟通、合同谈判和内部汇报 | 输出交易日志、复盘报告和客户说明 |

不同角色使用不同业务路线：

- **发电企业交易员**：成本、可用容量、中长期覆盖、现货报价、辅助服务和收益归因。
- **售电公司交易员**：客户负荷、购售组合、零售定价、偏差、信用和结算。
- **电力用户**：用电特性、零售合同、需求响应、购电成本和账单核验。
- **新能源/储能/VPP**：预测误差、SOC/可调能力、现货和辅助服务联合决策。

每天的业务训练按真实工作节奏组织：

```text
早间信息收集
  → 解读交易公告与边界条件
  → 更新负荷/新能源/价格预测
  → 核对合同和分时敞口
  → 制定并审批交易计划
  → 在窗口期完成申报
  → 核验出清结果和异常
  → 复核结算与偏差
  → 形成交易日志、日报和复盘
```

### 6.4 每一课必须有完整教学结构

```text
Lesson
  ├─ 学习目标和先修知识
  ├─ 生活化解释
  ├─ 专业定义、公式和规则条款
  ├─ 带单位的计算示例
  ├─ 真实数据图表
  ├─ 2—4 个即时检查
  ├─ 小实验或仿真任务
  ├─ 常见误区
  ├─ 本课总结
  └─ 间隔复习卡片
```

仅阅读文档或答对一次都不等于掌握。掌握度至少综合：

- 即时检查和延迟复测。
- 解释题与计算题。
- 仿真中是否正确应用。
- 多次表现的稳定性。
- 证据是否覆盖概念、计算和应用三个层级。

### 6.5 教材和知识库导入

教材导入不能只把 PDF 切成无结构文本。需要保留：

```text
Book
  → Edition
    → Chapter
      → Section
        → PageRange
          → Chunk
```

同时保存作者、出版社、ISBN、版本、页码、图表、公式、许可、原文件哈希和可见范围。

课程编译流程：

```text
导入合法持有的教材/官方资料
  → 目录与页码识别
  → 术语、概念、公式、案例和先修关系抽取
  → 映射知识图谱
  → 生成课程草稿、例题和实验建议
  → 引用核验和人工确认
  → 发布课程版本
```

AI 回答必须带教材页码或规则条款引用；找不到证据时明确说不知道。AI 生成的课程和题目在审核前标为草稿。

### 6.6 首批学习资料建议

第一优先使用免费、权威、可合法存储的资料：

- 《电力市场运行基本规则》及中长期、现货、辅助服务、计量结算、信息披露基础规则。
- 《电力交易员国家职业标准（2024 年版）》。
- 各省现行实施细则、交易操作指南和公开市场报告。
- 系统自行编写的基础讲义、术语、计算例题和仿真实验。

用户可以导入自己合法购买或获授权的教材，例如《电力现货市场101问》等。平台只保存用户私有副本和学习索引，不主动搜索或下载盗版电子书，不把受版权保护的全文变成公共知识库。

### 6.7 知识图谱是三个系统的连接层

```text
知识点
  ├─ 先修知识点
  ├─ 教材章节和页码
  ├─ 规则条款和版本
  ├─ 术语与公式
  ├─ 题目
  ├─ 数据指标
  ├─ 仿真场景
  └─ 用户掌握证据
```

例如“偏差结算”知识点同时连接：

- 计量结算规则条款。
- 教材相关章节。
- 计划、实际、偏差和价格数据字段。
- 一组概念题与计算题。
- 新能源预测偏差仿真案例。
- 用户在仿真中的错误和复习任务。

## 7. 首页与导航重构

产品不应把几十个后台动作全部放成一级菜单。个人版建议保留六个主入口：

1. **今日学习**：主动任务、连续学习、复习到期和能力进展。
2. **课程与知识库**：课程地图、教材、规则、术语和检索。
3. **市场数据**：数据目录、行情、报告、质量和来源。
4. **仿真实训**：入门实验、历史回放、综合案例和自由沙盘。
5. **交易工作台**：预测、合同、持仓、报价、结算和风险。
6. **考试与评估**：章节测验、模拟考试、项目评估和能力报告。

“规则设置、主体设置、场景设置、房间设置、出清”等属于案例编辑器或教师/管理员控制台，不应占据个人学习者的主导航。

## 8. 实施路线图

### P0：可信底座与学习内容模型（2—4 周）

- 建立数据源注册表、原始资产、标准数据集、质量状态和凭证引用。
- 实现教材层级、页码引用、许可和课程版本模型。
- 将 8 个粗知识点扩展为有先修关系的知识图谱。
- 建立规则包、规则条款和生效期模型。
- 学习首页改成真实任务流，不再把“开始学习”直接等同于刷题。

验收：任意数据和教学结论可回到来源；用户能完成一节真正的课并留下进度证据。

### P1：主动学习 MVP（3—5 周）

- 发布阶段 0、阶段 1 的首批 20—30 节微课。
- 发布首批交易员业务课：公告解读、交易计划、注册资料、申报表、结算单和风险台账。
- 完成阅读器、标注、术语弹窗、即时检查和间隔复习。
- 用稳定的多证据掌握度替换 8 题一次性诊断。
- 建立每日计划、弱项补课和学习提醒。
- 打通课程—题目—规则—知识库引用。

验收：新用户无需自己规划，连续 7 天都有合理任务；每个能力判断能展示证据。

### P2：真实数据历史回放（4—6 周）

- 只接入国内数据：国家规则/统计、首省公开披露、中国气象数据网历史数据和可替换的国内气象实况源。
- 建立市场日快照和真实/重构缺口说明。
- 实现 L0/L1 出清、96 点多段申报、确定性结果和简单结算。
- 发布 5—10 个“课程后小实验”和 3 个历史日案例。

验收：用户能从一节课进入真实数据案例，完成报价并得到规则与知识点复盘。

### P3：中长期—现货—结算闭环（6—10 周）

- 主体、资产、合同、持仓、账户和订单状态完整化。
- 中长期四种方式与日前/实时市场独立实现。
- 计划、实际、偏差和结算单贯通。
- 预测、敞口、风险和收益归因进入工作台。

验收：合同、电量、资金和结算可对账；同一输入可重复得到同一结果。

### P4：专业出清与新型主体（持续）

- SCUC/SCED、网络约束、节点价格和潮流。
- 辅助服务、储能、VPP、绿电/绿证。
- 多省规则差异、事件注入和压力测试。
- 市场监测、市场力和干预复盘。

### P5：多人教学

- 房间、教师控制台、主体分配、统一时钟、竞赛和班级报告。
- 房间只编排成熟的单人引擎，不复制业务逻辑。

## 9. 第一条推荐纵向切片

第一条切片同时验证数据、学习和仿真：

```text
课程：《为什么日前价格会在晚高峰上升》
  → 阅读规则和基础讲义
  → 查看某个真实历史日的负荷、新能源和价格
  → 回答 3 个即时检查
  → 预测 96 点价格区间
  → 以售电公司或发电企业身份提交简化多段报价
  → 运行确定性出清和偏差结算
  → 与历史结果及基准策略对比
  → 系统解释误差并安排下一课
```

它比先实现房间或继续增加交易菜单更能验证产品核心价值。

## 10. 完成定义

### 一项数据接入完成

- 有许可/披露范围、原始副本、哈希、解析版本和质量状态。
- 有失败告警、更新频率和修订记录。
- 前端明确显示时效与来源等级。

### 一节课程完成

- 有目标、先修、讲解、证据引用、检查、实验和复习。
- 能留下稳定的掌握证据，并影响后续计划。
- AI 内容经过审核或明确标记为草稿。

### 一项仿真能力完成

- 机制、单位、状态和权限正确。
- 数据来源清楚，结果确定且可复现。
- 订单、成交、持仓、资金和结算可对账。
- 能解释结果并回流到学习系统。
