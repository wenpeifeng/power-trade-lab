# 和风天气与国内真实数据接入手册

## 1. 当前已经打通的真实数据

### 国家能源局公开统计

无需账号，连接器 `nea_statistics` 已实现并完成首次真实采集：

- 全国月度全社会用电量及分产业用电量；
- 全国电力市场交易电量；
- 省内、跨省跨区、中长期、现货、绿电和代理购电分项；
- 绿证核发量、可交易量和交易量。

数据等级为 `observed_public`。标准化数据写入 `PublicData`，原始页面文本按
SHA-256 保存到 `data/raw/public/nea_statistics/`。系统每天 12:20 检查增量。

### 和风天气

连接器 `qweather` 已实现：

- 国内城市搜索；
- 实况天气；
- 24/72/168 小时逐小时预报；
- API KEY 与 Ed25519 JWT 两种认证；
- 原始响应、来源 URL、抓取时间、解析器版本、质量状态和哈希留档；
- 每小时第 5 分钟自动同步；
- 数据资产中心显示配置状态、测试连接和立即同步。

开源版本通过 `QWEATHER_ENABLED=false` 显式默认关闭。每个部署者必须注册并配置
自己的和风天气账号；作者账号、专属 API Host 和凭证不会随源码分发。

天气数据等级为 `observed_authorized`，作为负荷和新能源预测的外生特征，不冒充
电力交易中心行情。

## 2. 你需要准备什么

不要把 API KEY、私钥、Cookie 或 Token 发到聊天里。

### 方案 A：API KEY

需要在和风控制台找到：

1. 专属 API Host；
2. API KEY。

### 方案 B：JWT（推荐）

需要：

1. 专属 API Host；
2. Project ID；
3. Credential ID；
4. 与控制台公钥匹配的 Ed25519 私钥文件。

私钥只放在本机。系统配置只保存私钥文件路径，不保存或返回私钥内容。

## 3. 本机安全配置

在项目根目录运行：

```bash
backend/.venv/bin/python backend/scripts/configure_qweather.py
```

脚本会：

- 交互式询问认证方式和配置；
- 显式写入 `QWEATHER_ENABLED=true`；
- 使用不回显输入读取 API KEY；
- 将配置写入被 `.gitignore` 排除的 `backend/.env`；
- 将 `.env` 权限设为 `600`；
- 保留已有的非和风配置；
- JWT 私钥使用绝对路径。

配置后重启后端，然后在“数据资产中心 → API 数据源 → 和风天气”依次点击：

1. 刷新状态；
2. 测试连接；
3. 立即同步。

如需停止调用，把本机 `backend/.env` 中的 `QWEATHER_ENABLED` 改为 `false` 并重启。
即使其他凭证仍在本机，关闭总开关后也不会创建每小时天气任务。

也可以通过接口验收：

```text
GET  /api/asset/connectors/qweather/status
POST /api/asset/connectors/qweather/test
POST /api/asset/crawler/run        {"crawler_type":"weather"}
GET  /api/asset/crawler/status?crawler_type=weather
```

## 4. 默认覆盖范围

首批使用当前仿真系统的五个核心区域及省会：

- 山西—太原；
- 山东—济南；
- 广东—广州；
- 浙江—杭州；
- 蒙西—呼和浩特。

后续可通过 `QWEATHER_LOCATIONS_JSON` 添加或覆盖国内城市。天气城市不等于电力市场
分区；进入预测模型前必须按省份、气候区和电网分区做特征映射。

## 5. 真实数据边界

- 公众页面和公开附件可以依法、限频采集。
- 用户本人合法订阅的开发者 API 可以使用本地凭据同步。
- 只向市场成员披露的出清明细、结算明细和计量数据，个人账号无法合法获取时，
  系统只支持用户合法导出文件后导入，不绕过登录、验证码和权限。
- 按公开区间算法生成的曲线只能标记为 `reconstructed`，不得展示为实时或实测数据。
