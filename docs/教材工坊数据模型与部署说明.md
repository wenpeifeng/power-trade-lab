# 教材工坊数据模型与部署说明

## 目标与边界

教材工坊把用户合法持有的电力行业 PDF、DOC 或 DOCX 转换为个人学习资产。原文件和派生 Markdown 默认仅对上传用户可见，不自动进入公共知识库，也不对其他用户发布。

处理链路：

```text
上传与 SHA-256 去重
  → MinerU 转 Markdown（PDF 在 MinerU 不可用时可全文降级提取）
  → 电力行业相关性检测
  → 章节和原书页码重建
  → 章节重点、理解检查和笔记
  → 逐章进度与测验复盘
```

## 表结构与迁移

新增三张表：

- `learning_books`：原始文件、哈希、解析状态、行业相关性和整本进度。
- `learning_book_chapters`：章节 Markdown、页码范围、摘要、重点和题目快照。
- `learning_book_progress`：用户逐章状态、笔记、测验成绩和历次逐题复盘。

当前开发库仍由应用启动时的 `Base.metadata.create_all()` 创建新增表，不修改已有表，也不需要回填历史数据。生产部署前应改为正式迁移：

1. 按上述顺序建表，保留唯一约束 `user_id + raw_sha256`、`book_id + chapter_order`、`user_id + chapter_id`。
2. 先发布数据库迁移，再发布后端。
3. 旧用户无需回填；首次上传时创建个人教材记录。
4. 回滚应用版本前可保留三张表；它们不会影响旧版本查询。确需删除时，应先备份 `data/learning_books/` 和三张表。

## MinerU 部署

主应用通过 `MINERU_API_URL` 连接独立 MinerU 服务，避免把模型和交易 API 进程耦合：

```env
MINERU_ENABLED=true
MINERU_API_URL=http://127.0.0.1:18000
MINERU_BACKEND=hybrid-engine
MINERU_EFFORT=medium
MINERU_TIMEOUT_SEC=1800
```

服务需提供 `GET /health` 和同步 `POST /file_parse`。未配置时：

- 文本型 PDF 使用 `pdfplumber` 全文降级解析，并在解析引擎字段中明确标识。
- 扫描 PDF、DOC、DOCX 不伪装成功，提示连接 MinerU。

## 数据治理

- 原文件以 SHA-256 命名，接口按当前用户隔离。
- 非电力行业文档保留个人原始资产和 Markdown，但不生成学习课程。
- AI 题目只依据当前章节内容；无法生成时使用明确标识的章节理解检查，不写入权威公共题库。
- 删除、共享、许可信息和公共知识库晋级将在后续治理版本中补充，未实现前不得把私有教材视为公共数据资产。
