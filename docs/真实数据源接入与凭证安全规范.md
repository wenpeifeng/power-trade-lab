# 真实数据源接入与凭证安全规范

> 数据资产是本系统的基准核心。本规范定义哪些数据可以采集、怎样使用用户授权、如何保存原始数据，以及如何避免 Token 和私有市场数据泄露。

## 1. 能不能用用户 Token 采集

可以，但必须同时满足：

1. Token 属于用户本人或用户获得了组织的明确授权。
2. 平台条款、接口规则或数据导出功能允许该种访问方式。
3. 只访问 Token 权限范围内的数据，不提升权限、不绕过限制。
4. Token 不通过聊天传递，不写入代码、日志或普通数据库字段。
5. 用户能查看授权范围、最后同步时间并随时撤销。

如果平台没有 API Token，只提供网页登录，则优先让用户在本机浏览器中自行完成登录和二次认证。采集器可以复用经过授权的浏览器会话，但不得提取、展示或上传会话 Cookie。

## 2. 注册账号与市场注册不是一回事

### 公众访问

- 政府、监管机构和交易中心公开网站通常可以直接查看公众信息。
- 适合采集政策、规则、公告、公开成交结果、运行报告和附件。
- 不需要成为电力市场经营主体。

### 信息披露平台账号

- 部分地区允许注册账号或由市场主体账号进入信息披露平台。
- 登录后能看到的信息可能属于“向市场成员公开”或“特定信息”。
- 能否自动下载、是否提供接口、允许的频率，需要逐个平台确认。

### 电力市场经营主体注册

现行规则允许符合条件的企业、法人授权主体、个体工商户，以及执行工商业电价或具有分布式电源的自然人等申请。不同主体还需满足对应条件：

- 发电企业：项目核准/备案、发电许可或豁免、并网调度、计量。
- 电力用户：通常为工商业用户，并具备计量和结算能力。
- 售电公司：按照售电公司管理规则注册。
- 储能、虚拟电厂、分布式电源等：需要并网/负荷协议、分时计量、调度或控制能力等。

纯个人学习者如果不具备工商业用电、分布式电源或其他主体条件，通常不能仅为获取数据而注册成经营主体。

## 3. 数据接入优先级

按稳定性和合规性排序：

| 优先级 | 接入方式 | 适用情况 |
|---|---|---|
| 1 | 官方开放 API / OAuth | 最稳定，可增量同步和审计 |
| 2 | 官方数据接口 + 用户 Token | 市场成员或订阅账号授权 |
| 3 | 官方导出文件 | Excel、CSV、PDF、结算单、历史报表 |
| 4 | 公开网页/附件采集 | 无接口的公众信息 |
| 5 | 授权浏览器会话 | 登录后允许访问但无 API/导出接口 |
| 6 | 重构/合成 | 真实数据缺失时的教学补充，必须明确标注 |

不能以浏览器自动化绕过验证码、二次认证、访问控制或接口频率限制。

## 4. 凭证保存方案

### 本地个人版

推荐顺序：

1. macOS Keychain / Windows Credential Manager / Linux Secret Service。
2. 仅本机可读的环境变量或 `.env`。
3. Playwright 持久化登录配置目录，仅保存在本机并限制文件权限。

数据库只保存：

```text
credential_ref       钥匙串或密钥服务引用
connector_id         连接器
account_label        脱敏账号名称
scopes               授权范围
expires_at           过期时间
last_sync_at         最后同步
status               active/expired/revoked/error
```

### 多用户部署

- 使用 Vault、云 KMS 或平台 Secret Manager。
- 每个用户/机构独立密钥和访问策略。
- Token 加密存储、传输全程 TLS、定期轮换。
- 管理员也不能在后台页面看到完整 Token。

## 5. 连接器标准流程

```text
登记数据源
  → 用户查看所需权限
  → 用户在本机或官方页面完成授权
  → 保存凭证引用
  → 连接测试
  → 首次全量同步
  → 增量同步
  → 原始数据落地
  → 标准化/质量校验/去重
  → 发布到数据资产目录
  → 监控过期、异常和权限撤销
```

每个连接器需要实现：

- `test_connection`
- `discover_capabilities`
- `sync_incremental`
- `download_raw`
- `normalize`
- `validate_quality`
- `refresh_authorization`
- `revoke`

## 6. 原始层与标准层

真实数据必须先保存原始副本，再进入标准模型：

```text
RawAsset
  source_url / fetched_at / http_status
  content_type / file_path / sha256
  connector_id / authorization_scope
  publish_time / original_filename

NormalizedDataset
  province / market / product / data_type
  interval / unit / time_range
  provenance_level / disclosure_scope
  parser_version / quality_status
  raw_asset_id
```

原始层不可被标准化结果覆盖。解析器升级后应能从同一原始文件重新生成标准数据。

## 7. 数据权限分层

| 数据范围 | 保存与使用要求 |
|---|---|
| 公众信息 | 可进入公共数据资产，保留来源与版权/使用说明 |
| 市场成员公开信息 | 仅对具备对应授权的用户或机构展示 |
| 特定/私有信息 | 严格按所属主体隔离，不进入公共搜索或公共训练集 |
| 用户上传数据 | 默认私有，未经明确授权不得共享 |
| 重构/合成数据 | 可用于教学，但必须与真实观测分开展示和统计 |

RAG、AI 出题、策略训练和报表生成必须继承原数据的权限，不得通过 AI 回答泄露私有数据。

## 8. 审计与撤销

记录但不包含敏感值：

- 谁在什么时间授权了哪个连接器。
- 使用了哪些 scope。
- 每次同步的时间、结果、数据量和错误类型。
- 哪些数据来自哪个授权账号。
- Token 刷新、过期和撤销事件。

用户撤销后：

1. 停止定时任务。
2. 删除本地凭证和刷新令牌。
3. 将连接器状态改为 `revoked`。
4. 根据用户选择保留或删除已同步的私有数据。
5. 保留不含敏感内容的最小审计记录。

## 9. 首批建议接入

在确定省份前，先建设通用连接器框架。确定省份后按以下顺序落地：

1. 国家发展改革委、国家能源局及派出机构的规则和政策。
2. 对应省电力交易中心公众信息、公告和附件。
3. 对应省信息披露平台的公开数据。
4. 用户合法账号可导出的市场成员数据。
5. 用户自己的合同、计量、结算单和历史用电文件。

首批不要同时覆盖全国。先选择一个用户最关注、又有稳定数据入口的省份，跑通“原始数据—标准化—质量校验—历史仿真—学习复盘”闭环。

近期产品只接入国内数据：

| 平台/来源 | 账号/密钥 | 适用数据 |
|---|---|---|
| 国家发展改革委、国家能源局及派出机构 | 无需账号 | 国家规则、省级细则、监管信息和统计 |
| 北京、广州和省级电力交易中心公众区 | 通常无需账号 | 公告、公开交易结果、市场报告和附件 |
| 省级信息披露平台公众区 | 逐省确认 | D+1 聚合量价、负荷、出力、备用等公开字段 |
| 国家统计局“国家数据” | 无需账号或公开查询 | 分省发电量、能源生产和宏观指标 |
| 中国气象数据网 | 个人/教育科研实名注册 | 历史日值、逐三小时观测、再分析数据 |
| 国内开发者气象服务 | 用户本人申请 KEY | 气象实况、逐小时预报和格点天气 |
| 用户合法导出的本地文件 | 不接管登录凭证 | 合同、计量、结算、实际用电等私有数据 |

旧 SmartWeatherAPI 页面依赖的申请表下载入口不稳定，不作为产品连接器。中国气象数据网用于权威历史数据；需要实时气象时使用可替换的国内开发者 API。国外交易数据暂不进入数据目录和路线图。

### 已落地连接器（2026-07）

- `nea_statistics`：国家能源局月度用电量、市场交易电量、全国装机与利用小时、
  绿证核发交易及价格梯度、新能源项目建档，
  `observed_public`，已保存原文快照和 SHA-256。
- `nbs_energy`：国家统计局月度能源生产，`observed_public`。
- `gzpec_market`：广州电力交易中心南方现货周行情与绿证周行情，
  `observed_public`。
- `carbon_market`：上海环境能源交易所全国碳市场 CEA 日行情，
  `observed_public`，展示与转载需遵守原站声明。
- `qweather`：和风天气实况与逐小时预报，`observed_authorized`，支持 API KEY/JWT；
  配置与验收见《和风天气与国内真实数据接入手册》。

上述公开网页连接器使用 `CrawlSourceItem` 进行原文级增量同步：官方文章 ID
（或规范化 URL 哈希）作为唯一标识；已成功且解析器版本未变化的原文不再请求
详情页，失败项和解析器升级项才会重试。标准化数据仍使用业务键二次去重。
