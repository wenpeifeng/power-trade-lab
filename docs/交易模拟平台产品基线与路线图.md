# 电力交易模拟平台 · 产品基线与路线图

> 基于当前仓库实现、历史 Claude Code 方案、用户提供的竞品截图和国家电力市场基础规则整理。本文用于回答两个问题：当前到底完成了什么，以及下一步怎样从“可演示终端”走向“以真实规则和真实数据为底座的学习型仿真平台”。

本文保留交易仿真的专项基线。数据资产、个人可注册数据平台、主动学习、教材知识库和统一实施顺序，见 [《全面产品重构方案：数据资产、专业仿真与主动学习》](./全面产品重构方案-数据仿真与主动学习.md)。

产品目标不是复刻某个竞品界面，而是：

1. 辅助学习电力交易员岗位知识和实际操作。
2. 帮助理解电力市场、电力系统、价格形成与结算等专业知识。
3. 采集并使用来源清晰的真实数据进行历史回放和模拟交易。

## 1. 当前结论

学习、考试、政策、知识库和 AI 检索已经形成界面与模型骨架；交易模块仍处在 MVP 演示阶段。当前开发数据库中课程和课时均为 0，只有 20 道题，因此学习中心也不能再描述为已经形成完整学习体系。

当前交易路径是：

```text
选择市场/省份/日期
  → 查看 96 点价格曲线
  → 输入单段价格和电量
  → 基于历史均价与随机虚拟流动性立即撮合
  → 显示成交记录
  → 用报价与均价之差生成简单复盘
```

它可以演示“报价影响成交”，但还不能模拟一场真实的电力市场组织过程。

## 2. 当前能力盘点

### 已实现或基本可用

- Vue 3 + FastAPI 的前后端基础架构和登录认证。
- 学习刷题：知识点组卷、判分、错题本、相关资料推荐。
- 模拟考试：蓝图、组卷、计时、交卷、历史结果。
- 分层学习：能力诊断、偏好、省份学习内容。
- 政策新闻流、知识库、多源数据接入和混合检索。
- 交易市场列表：中长期、日前、实时、调频、绿电。
- 交易行情：五省切换、日期回放、96 点价格曲线。
- 单段买卖申报、虚拟撮合、成交列表和简单策略复盘。
- 各模块评估脚本和统一回归入口。

### 有模型或接口，但没有闭环

- `TradePosition` 已建模，但成交后没有真正维护持仓。
- `TradeAccount` 有余额和冻结字段，但申报/成交没有扣款、冻结或解冻。
- 订单只有 `pending/filled/canceled` 注释，当前提交后总是标为 `filled`，即便只成交一小部分。
- 订单簿接口存在，但前端没有展示，数据也是按出清价生成的虚拟盘口。
- 市场列表看似覆盖五类品种，底层却共用同一套撮合逻辑。
- 行情响应包含负荷字段，但交易终端只展示价格。

### 尚未形成

- 案例实例、市场主体和资产分配。
- 仿真时钟、申报窗口、封盘、出清、结算等流程状态机。
- 交易规则配置、市场边界和省份规则版本。
- 发电机组、售电公司、用户负荷、储能等资产模型。
- 24/96 时段多段报价曲线编辑器。
- 确定性供需曲线、集中竞价和现货出清引擎。
- 日前计划、实时偏差和最终结算。
- 事件注入、消息公告、管理员控制台。
- 可选的多人协作、教师带班和排行榜/教学评估。
- 复盘到知识点、课程和错题的学习闭环。

## 3. 与竞品截图的能力对照

截图的价值在于展示了较完整的业务对象和交易类型，但不应照抄它的页面层级。系统需要的是“数据真实、规则配置化、流程可回放、结果可解释”，而不是“菜单数量相同”。

| 竞品截图可见能力 | 当前项目 | 判断 |
|---|---|---|
| 创建房间、加入房间、当前房间 | 无房间模型 | 多人教学时需要，单人仿真不需要 |
| 房间参数设置 | 只有市场/省份/日期切换 | 应先沉淀为“仿真任务参数” |
| 市场主体设置、成员持仓设置 | 只有单用户账户与未使用的持仓模型 | 核心缺口 |
| 场景信息设置 | 只有价格/负荷数据 | 核心缺口 |
| 交易序列设置、仿真流程 | 提交后立即撮合 | 核心缺口 |
| 交易规则设置 | 市场名称存在，规则未配置化 | 核心缺口 |
| 集中竞价出清、现货出清 | 统一调用简化随机撮合 | 核心缺口 |
| 中长期合约对比、现货报价对比 | 只有报价与单一均价对比 | 明显不足 |
| 市场总览、机组、新能源、负荷、联络线、约束 | 仅价格曲线，负荷未展示 | 明显不足 |
| 默认案例、案例图形编辑 | 无案例版本和拓扑 | 后续能力 |
| 房间用户、实时事件 | 无多人状态和事件流 | 后续能力 |

因此，下一阶段不应先继续增加左侧菜单，而应先补齐真实数据底座和无需房间也能运行的仿真内核。

### 3.1 房间到底有什么作用

房间是一个**教学和协作容器**，不属于电力交易市场机制本身。

适合使用房间的场景：

- 教师组织一批学员在同一案例、同一市场时钟下演练。
- 多个学员分别扮演发电企业、售电公司、电力用户或储能。
- 团队竞赛、策略博弈、统一封盘和统一公布结果。
- 教师控制阶段、注入事件、查看所有成员提交状态。

不需要房间的场景：

- 个人学习一条规则。
- 使用历史真实数据完成一次日前报价。
- 练习中长期集中竞价或查看结算计算过程。
- 回放历史市场并与真实结果对比。

因此系统的核心对象应是 `SimulationRun`（仿真任务实例），房间只是未来把多个用户和仿真任务组织起来的可选上层能力。

### 3.2 完整功能版图

按照真实业务，而不是按照截图菜单，目标能力分为九层：

| 能力层 | 应包含的核心功能 |
|---|---|
| 规则与知识 | 国家基础规则、省级实施细则、交易员知识树、术语、规则版本和条款关联 |
| 真实数据 | 政策公告、市场披露、交易结果、分时价格、负荷、新能源出力、检修、断面、联络线、备用、煤价/碳价 |
| 市场主体 | 发电企业、售电公司、电力用户、储能、虚拟电厂、智能微电网及其准入/档案 |
| 资产与约束 | 火电、水电、风电、光伏、储能、负荷；容量、成本、爬坡、启停、SOC、预测误差和网络约束 |
| 中长期市场 | 年/月/月内交易，双边协商、集中竞价、滚动撮合、挂牌摘牌、合同转让、绿电交易 |
| 现货市场 | 日前、日内、实时，96 点申报、机组组合、经济调度、统一/分区/节点价格、安全约束 |
| 零售与结算 | 零售套餐/合同、实际用电、计量数据、中长期与现货衔接、偏差、结算单、追退补 |
| 辅助服务 | 调峰、调频、备用、爬坡，需求、申报、出清、调用、费用计算和分摊 |
| 学习与复盘 | 流程教学、操作练习、策略评分、真实结果对比、知识点定位、题目和课程推荐 |

后台“交易规则设置、主体设置、场景设置、市场设置、出清”等功能是以上业务层的管理入口；它们不是最终产品价值本身。

## 4. 当前实现中的主要风险

### 4.1 数据真实性标签不准确

`backend/crawlers/adapters/market_data.py` 中的 96 点电价和负荷是根据公开区间与峰谷参数生成的重构曲线，并非交易中心逐点原始行情；但交易接口会把 `PublicData` 中的数据统一返回为 `data_source="real"`。

建议立即改为三级来源：

```text
observed      原始观测数据
reconstructed 基于公开统计重构
synthetic     教学合成
```

这是产品可信度问题，优先级高于增加图表。

### 4.2 撮合结果不稳定

撮合路径中直接使用未固定种子的 `random.uniform`，相同报价重复提交可能得到不同成交量，无法严格回放，也无法用于公平的教学排名。

### 4.3 订单状态与成交事实不一致

即使成交量小于申报量，订单仍被写成 `filled`；零成交也会创建成交记录。应至少支持：

```text
draft → submitted → accepted/rejected
      → open → partially_filled → filled/canceled/expired
```

### 4.4 账户、持仓和结算没有生效

交易账户只读不动，持仓表未维护，复盘中的 `potential_pnl` 也不是可对账结算收益。当前“账户余额”和“策略盈亏”容易给用户造成闭环已经完成的错觉。

### 4.5 市场品种只是标签

中长期、日前、实时、调频和绿电目前共用一套简化撮合。产品层应把“市场品种”升级为“规则包 + 流程 + 申报模型 + 出清策略 + 结算策略”。

### 4.6 “真实数据”不能简单等于“爬到的数据”

电力市场信息按披露范围分为公众信息、向市场成员公开的信息和特定信息。系统能够合法自动采集的主要是公众信息；需要市场成员登录、授权或只向特定主体披露的数据，不能通过绕过权限的方式抓取。

真实数据建设应区分：

| 等级 | 定义 | 用途 |
|---|---|---|
| `observed_public` | 官方公开页面、公告、附件或开放接口中的原始数据 | 公开行情、历史回放、规则研究 |
| `observed_authorized` | 用户以合法市场成员身份授权导入/同步的数据 | 更完整的个人或机构仿真 |
| `reconstructed` | 根据公开统计、典型曲线和边界重构 | 缺失字段补全、教学案例 |
| `synthetic` | 完全由场景生成器产生 | 极端情景、入门练习、测试 |

每条数据至少保存：

```text
source_url / source_org / fetched_at / publish_time
market / province / data_type / interval / unit
disclosure_scope / provenance_level
raw_file_hash / parser_version / quality_status
```

原始文件和原始响应要先落地，再做标准化。解析后的数据必须能追溯回原文、原表或原接口响应。

## 5. 目标领域模型

建议用以下最小领域骨架承载后续功能：

```text
SimulationCase（案例模板）
  ├─ RulePackage（省份/品种/版本）
  ├─ ScenarioDataset（负荷、出力、价格、联络线、约束）
  ├─ ParticipantTemplate（主体模板）
  └─ AssetTemplate（机组、负荷、储能）

SimulationRun（一次仿真任务实例）
  ├─ ParticipantAssignment（用户或系统扮演的市场主体）
  ├─ SimulationRound（年度/月度/日前/实时等轮次）
  ├─ MarketPhase（准备/申报/封盘/出清/结算/复盘）
  ├─ Bid（分时、多段量价）
  ├─ ClearingRun（输入快照、引擎、版本、种子）
  ├─ DispatchSchedule（成交/计划曲线）
  ├─ SettlementStatement（可对账结算单）
  └─ LearningFeedback（知识点与改进建议）

SimulationRoom（可选的多人教学容器）
  ├─ RoomMember（教师/学员/观察员）
  ├─ SharedClock（统一时钟与阶段控制）
  └─ SimulationRun[]（同一案例下的个人或团队实例）
```

每次仿真引用案例的不可变版本，避免规则更新后历史结果无法复现。

## 6. 分阶段路线图

### P0：真实数据与规则底座

目标：先保证系统知道“数据从哪里来、规则按哪个版本执行”，同时把当前错误的真实性标签修正。

- 建立数据源注册表：机构、URL、数据类型、频率、披露范围、采集方式和许可说明。
- 先接入一个省份的官方规则、市场公告、成交/出清披露和可获得的分时数据。
- 原始页面、PDF、Excel、CSV、接口响应落地并计算哈希。
- 建立 `observed_public / observed_authorized / reconstructed / synthetic` 来源分级。
- 建立数据质量规则：完整性、时间粒度、单位、重复、异常值、缺失点和版本。
- 建立国家基础规则与首省规则包，规则条款关联知识点、题目和计算公式。
- 建立数据库迁移方式和正式请求/响应模型。

验收标准：

- 任意数据可追溯到原始来源、抓取时间、解析版本和质量状态。
- 前端不会把重构/合成数据显示成真实观测。
- 首个省份有可搜索、可版本化、可关联知识点的完整规则包。
- 采集失败、页面变化和数据异常会告警，不会静默写入错误数据。

### P1：单人日前现货学习仿真

目标：不依赖房间，使用同一省份的规则和历史真实数据完成一次可复现的日前仿真。

- 建立 `SimulationRun`、主体、资产、阶段和不可变输入快照。
- 引入状态机：准备 → 申报 → 封盘 → 出清 → 结算 → 复盘。
- 发电企业与售电/负荷侧两类主体。
- 机组、负荷、新能源、备用和联络线等基础边界。
- 96 点、多段量价曲线编辑和批量填报。
- 确定性的供需曲线、统一边际出清和部分成交。
- 订单校验、正确状态流转、取消/过期和审计日志。
- 固定场景随机种子；历史回放默认不引入随机性。
- 计划电量、实际电量、偏差和结算单。
- 用户报价、仿真结果、历史真实结果和基准策略四方对比复盘。
- 将复盘错误映射到规则条款、知识点和练习题。

验收标准：

- 完成一场从准备到结算的完整仿真。
- 相同输入重复运行结果完全一致。
- 电量和资金可对账。
- 约束触发与未成交原因可解释。
- 用户能看到报价如何改变成交与收益，并知道对应的规则依据。

### P2：中长期、零售与现货衔接

目标：让用户理解交易员工作不只有现货报价，还包括合约管理、零售服务和风险敞口。

- 中长期双边协商、集中竞价、滚动撮合和挂牌摘牌独立实现。
- 年、月、月内和分时合同曲线。
- 合同持仓、合同转让、履约和中长期—现货敞口。
- 售电公司零售套餐、零售合同、用户实际用电和零售结算。
- 绿电合同和环境价值/绿证关联。
- 市场总览、合约对比、报价对比、持仓与风险看板。
- 对每种交易方式提供流程教学、规则解释和专项练习。

验收标准：

- 四种中长期交易方式不能共用错误的单一撮合语义。
- 合约、现货、实际用电和结算能够贯通对账。
- 用户可以解释自己的合约敞口和偏差风险。

### P3：辅助服务、新型主体与系统约束

- 日内和实时市场，日前—实时偏差衔接。
- 调峰、调频、备用和爬坡；独立出清并为联合出清预留接口。
- 储能、虚拟电厂、智能微电网等新型主体。
- 多机组组合、储能 SOC、爬坡、启停和最小开停机约束。
- 节点电价、网络约束和拓扑图形编辑。
- 更多省份规则包、数据源和差异对比。
- 策略回测、压力测试和风险监控。

### P4：多人教学和机构运营

- 教师创建课程案例、分配主体、控制阶段和发布事件。
- 学员加入房间，分别扮演发电企业、售电公司、用户或储能。
- 统一仿真时钟、提交状态、事件流、公告和结果发布。
- 自动评分：合规性、收益、风险、预测误差和策略质量。
- 团队竞赛、排行榜、班级报告和机构运营看板。
- 预置案例：高峰保供、负电价、新能源偏差、阻塞、极端天气等。

## 7. 第一条推荐实施切片

第一条纵向切片建议选“单用户、单省份、单个历史日、日前现货、两类主体”：

```text
系统采集并固化官方规则与历史真实数据
  → 用户选择一个历史日和市场主体
  → 系统创建不可变的仿真任务快照
  → 展示 96 点负荷/新能源预测和市场边界
  → 用户提交 96 点多段报价
  → 系统封盘并运行确定性出清
  → 生成成交计划和结算单
  → 与历史真实结果和基准策略对比
  → 输出策略解释、规则依据和关联知识点
```

这条切片不需要房间，却能同时验证真实数据、规则、主体、场景、申报、出清、结算和学习反馈。完成后再扩展中长期、实时、辅助服务和多人教学，复用价值最高。

## 8. 暂不优先

- 在没有规则与状态机前继续增加更多交易品种入口。
- 用更多随机曲线营造“数据丰富”的视觉效果。
- 先做复杂电网拓扑编辑器，再补订单和结算。
- 只做竞品菜单一比一复制，不验证每项能力是否进入仿真闭环。
- 只优化深色交易大屏而不修复来源、状态和对账问题。

## 9. 产品验收总原则

一项交易功能只有同时满足以下四点，才算完成：

1. **业务正确**：符合该市场机制和单位约束。
2. **数据可信**：来源与生成方式清晰。
3. **结果可复现**：相同输入得到相同输出。
4. **教学有效**：用户知道为什么、错在哪里、下一步学什么。

## 10. 当前规则依据

产品设计和规则包优先依据官方现行文件，不以竞品页面或二手文章作为业务真值：

- [《电力市场运行基本规则》2024年第20号令](https://www.ndrc.gov.cn/xxgk/zcfb/fzggwl/202405/t20240510_1377245_ext.html)：市场运行的总纲。
- [《电力市场注册基本规则》](https://zfxxgk.nea.gov.cn/2024-09/13/c_1212399683.htm)：主体范围包含发电企业、售电公司、电力用户以及储能、虚拟电厂、智能微电网等新型主体。
- [《电力中长期市场基本规则》](https://zfxxgk.ndrc.gov.cn/web/iteminfo.jsp?id=20581)：自 2026 年 3 月 1 日起施行，覆盖集中竞价、滚动撮合、挂牌、绿色电力、执行和结算。
- [《电力现货市场基本规则（试行）》](https://zfxxgk.ndrc.gov.cn/web/iteminfo.jsp?id=20272)：覆盖日前、日内、实时市场，以及负荷预测、备用、机组/网络约束、出清和市场衔接。
- [《电力辅助服务市场基本规则》](https://www.nea.gov.cn/20250429/df8e465e859245039b24fbbe21f04c5f/1590532f26ed4320ab7f6c86757f5c42.pdf)：覆盖调峰、调频、备用、爬坡等服务的需求、交易、调用和费用。
- [《电力市场计量结算基本规则》](https://zfxxgk.ndrc.gov.cn/web/iteminfo.jsp?id=20533)：明确合同、出清、调度执行、辅助服务、计量和规则文件等结算基础数据。
- [《电力市场信息披露基本规则》](https://zfxxgk.nea.gov.cn/2024-01/31/c_1310763726.htm)：规范公众、市场成员和特定范围的信息披露及数据接口。

省级仿真规则必须在上述国家基础规则之上，再绑定对应省份当前有效的实施细则和参数版本。
