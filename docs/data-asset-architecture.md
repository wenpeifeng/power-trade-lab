# 数据资产中心 · 架构与归档规范

> 本文档是整个系统的**数据基座设计规范**。所有上层模块（学习/考试/交易/AI助手）都依赖此数据资产做扩展。

## 🆕 向量知识库（AI检索召回基座）

知识库已升级为**向量化的语义知识库**，支撑AI检索召回：

### 技术架构
- **Embedding模型**：BAAI/bge-small-zh-v1.5（中文语义，512维，本地运行）
- **分块策略**：每块~300字，块间重叠50字（保证语义连贯）
- **检索算法**：余弦相似度，内存计算（万级chunk毫秒级）
- **自动闭环**：文档入库 → 自动分块 → 自动向量化 → 可检索

### 语义检索能力（超越关键词）
| 查询 | 关键词搜索 | 语义检索 |
|------|-----------|---------|
| "电价怎么计算" | 可能找不到 | ✓ 召回结算规则 |
| "新能源卖电" | 找不到(无"卖"字) | ✓ 召回绿电绿证 |
| "风电光伏怎么交易" | 可能找不到 | ✓ 召回绿电机制 |

### 检索API
- `GET /knowledge/search?q=查询&top_k=5` 语义检索
- 支持 doc_type / province / knowledge_point_id 过滤
- `POST /knowledge/rebuild-index` 重建全量索引

### 支撑的四个场景
1. **AI助手问答召回**：用户提问 → 语义检索 → 召回相关知识 → 生成回答
2. **学习刷题知识关联**：学某知识点 → 检索关联政策/案例
3. **交易规则实时检索**：交易时 → 按省份过滤检索适用规则
4. **政策归纳关联**：相似政策聚类，形成政策演进时间线

## 一、核心定位

数据资产是系统的**第一核心**，三大价值：
1. **知识沉淀**：持续积累电力行业政策/规则/数据，形成自有知识库
2. **商业推广**：数据资产本身可作为产品（API/报告/数据库授权）
3. **基座赋能**：考试刷题、真实交易、政策解读都建立在数据之上

## 二、多源接入方式

系统支持 **5 种数据接入方式**。文档内容归档到 `KnowledgeDoc`，结构化时序数据
归档到 `PublicData`，原文处理状态归档到 `CrawlSourceItem`：

| 方式 | 标识 | 场景 | 操作 |
|------|------|------|------|
| 🔗 cURL抓取 | `curl` | 用户发现一个网页/文件，粘贴curl命令立即沉淀 | 粘贴curl → 自动解析抓取 → AI总结 → 归档 |
| 🕸️ 爬虫采集 | `crawler` | 定时自动抓取15个权威源 | 后台调度 + 手动按类型触发 |
| 📎 文件上传 | `upload` | 用户有PDF/Word/Excel文件 | 上传 → 解析文本 → AI总结 → 归档 |
| 📕 飞书导入 | `feishu` | 从飞书知识库批量导入已有资料 | 提供wiki token → 拉取 → 归档 |
| ✍️ 手动录入 | `manual` | 用户直接写文章 | 标题+正文 → AI总结 → 归档 |

## 三、归档分类体系

每份数据资产按 **4个维度** 分类组织，确保可检索、可筛选、可时间线浏览：

### 维度1：文档类型（doc_type）
| 类型 | 标识 | 来源 |
|------|------|------|
| 国家政策 | `national_policy` | 发改委/能源局/国务院 |
| 监管规则 | `regulation` | 6个区域能源监管局 |
| 交易中心公告 | `exchange_info` | 省级电力交易中心 |
| 行业资讯 | `industry_news` | 中电联/南网/行业媒体 |
| 考试信息 | `exam_info` | 中电联测评中心 |

### 维度2：省份（province）
- 全国级文档：`province = null`
- 省级文档：`province = "浙江"` / `"山西"` / ...（覆盖11+省份）

### 维度3：区域（region）
- 华北 / 东北 / 西北 / 华东 / 华中 / 南方

### 维度4：电网体系（grid）
- `sgcc` 国家电网 / `csg` 南方电网 / `impc` 蒙西电网

## 四、AI自动处理

所有接入的内容自动经过AI处理：

1. **AI摘要**：一段话总结核心要点（≤80字）
2. **AI关键词**：提取3-5个关键词
3. **自动分类**：基于标题内容判断doc_type
4. **知识点关联**：自动匹配到知识体系树的8大模块
5. **去重**：标题+日期hash去重，避免重复归档

> 无LLM时降级为规则提取（前80字摘要 + 关键词词库匹配）。
> 配置Ollama/OpenAI后启用高质量AI总结。

## 五、时间线归档

所有数据按 **发布日期** 组织时间线：
- 最新在前，按日期分组
- 每条标注来源方式（curl/爬虫/上传/飞书/录入）
- 支持 按类型+省份 筛选时间线

## 七、爬虫类型细分

后台支持按类型手动触发爬虫：

| 类型 | 标识 | 抓取内容 | 数据源 |
|------|------|---------|--------|
| 政策法规 | `policy` | 发改委/能源局/监管局政策 | gov_policy + standard_pdf |
| 考题真题 | `exam` | 知乎/B站真题回忆 | zhihu_bilibili |
| 交易数据 | `trade_data` | 出清价/负荷/新能源出力 | 待接入具体API |
| 行业新闻 | `news` | 中电联/南网/行业资讯 | gov_policy |
| 全部 | `all` | 所有源 | 全部爬虫 |

### 增量采集与唯一标识

公开网站连接器采用“列表发现 → 原文账本判断 → 只抓新增详情 → 原始快照 →
标准化”的流程，不能仅依赖入库阶段去重：

- `crawler_name + source_item_id` 是原文级唯一键。
- `source_item_id` 优先取官网 URL 中的文章 ID，无法提取时使用规范化 URL 的
  SHA-256；跟踪参数和 fragment 不参与身份计算。
- `CrawlSourceItem` 记录原文 URL、标题、官方发布日期（如有）、首次发现时间、
  成功/失败状态、内容 SHA-256、解析器版本、最后尝试和最后成功时间。
- `status=success` 且解析器版本未变化时，后续任务只扫描列表页，不重复下载详情。
- 上次失败或解析器版本升级时允许重试；成功状态与标准化数据在同一事务提交。
- `PublicData.dedup_key` 继续负责数据点级幂等，原文账本与数据点去重不可相互替代。
- 管理审计接口 `GET /api/admin/crawler/items` 可按 `crawler_name`、`status`
  查看唯一标识、原文链接、状态、哈希、版本和处理时间。

升级已有开发库时，`init_db()` 会创建新表；连接器首次运行会从已有
`PublicData.source_url` 回填成功账本，并保留历史 `parser_version`。因此不会
重下同版本原文，解析器升级后又能有条件地重新处理。该回填不删除、不重建
已有 SQLite 数据。

## 八、商业推广价值

数据资产作为独立商业产品：
1. **数据API**：出清价/政策/题库 API 对外授权
2. **行业研报**：基于沉淀数据自动生成分析报告
3. **数据库授权**：企业版提供完整知识库下载
4. **AI训练语料**：高质量电力行业语料库
